# Project Brief — Pizza Ville

## Overview
| Field | Value |
|---|---|

| Location | Disraeli, Quebec, Canada |
| Industry | Restaurant / Pizzeria |
| Project type | Brand-new professional client website |
| Status | 🟡 Foundation phase — no UI built yet |
| Start date | 2026-08-10 |

## Goal
Build a clean, modern, production-ready website for Pizza Ville that represents the
business professionally online, makes it easy for local customers in Disraeli (and
the surrounding Appalaches / Chaudière-Appalaches region) to find hours, location,
menu, and contact info, and — depending on scope decided later — supports online
ordering, reservations, or catering inquiries.

## What this document is
The top-level brief for the project. It links out to the other planning docs. Nothing
here should be treated as final until confirmed with the client (Pizza Ville).

## Known facts (confirmed)
- Business name: **Pizza Ville**
- City: **Disraeli, QC, Canada**
- Category: Restaurant / Pizzeria

## Explicitly NOT known yet (do not invent)
- Exact address / postal code
- Phone number, email
- Hours of operation
- Menu items, prices, sizes, combos
- Photos of food, storefront, interior, staff
- Logo / brand colors / existing brand assets (if any)
- Social media accounts (Facebook/Instagram)
- Online ordering provider (if any — e.g. own system, UberEats, DoorDash, Menufy, etc.)
- Domain name / hosting preferences
- Competitors in Disraeli / target audience specifics
- Tone of voice preference (family-friendly, casual, upscale, etc.)
- Existing reviews (Google, Facebook) to reference

All of the above must be supplied by the client before content is finalized. See
[BUSINESS-INFO.md](./BUSINESS-INFO.md) for the intake template.

## Project phases
1. **Foundation** (this phase) — docs, folder structure, tech scaffold. ✅ in progress
2. **Discovery** — collect real business info, photos, menu, branding assets
3. **Design system** — define visual language once brand direction is confirmed
4. **Content** — write real copy from real business info
5. **Build** — implement pages/components in Next.js
6. **SEO & launch prep** — metadata, local SEO, performance, accessibility
7. **Launch**

## Tech stack (decided)
- **Framework:** Next.js (App Router) + TypeScript
- **Styling:** Tailwind CSS
- **Hosting target:** TBD (Vercel is the natural default for Next.js — to confirm)
- **CMS:** TBD — none yet; content will start hard-coded/static and can migrate to a
  headless CMS later if the client wants self-service menu editing
